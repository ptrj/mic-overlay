# DEB, RPM and Arch/AUR packaging

All packages contain the executable, application desktop launcher, icon,
configuration example, English documentation and GPL-3.0-only license. They do
not install a background service or enable autostart for users automatically.

Author and maintainer: **ptrj <aur@dbs.sk>**.
Upstream repository: [ptrj/mic-overlay](https://github.com/ptrj/mic-overlay).
DEB/RPM homepage metadata and the Arch recipe use this URL.

## Distribution builds

Build against the target distribution's libraries, rather than repackaging an
Arch executable for another ABI. Qt >= 6.5 and LayerShellQt >= 6.6 are required.

```bash
bash scripts/package.sh deb
bash scripts/package.sh rpm
```

The supplied images use Ubuntu 26.04 and Fedora 44. Builds run CTest and CPack;
outputs are under `build-container/package-deb/packages/` and
`build-container/package-rpm/packages/`. Build containers do not share host audio
or Wayland. The first image build downloads development dependencies.

For a native DEB build, install build-essential, cmake, ninja-build,
qt6-base-dev, qt6-declarative-dev, qt6-wayland-dev, qt6-svg-dev,
liblayershellqtinterface-dev, layer-shell-qt, qt6-wayland, qt6-svg-plugins,
qml6-module-qtquick, qml6-module-qtquick-window, qml6-module-qtquick-layouts,
qml6-module-qtqml-workerscript, pipewire-bin, wireplumber, dpkg-dev and file.

For a native Fedora RPM build, install gcc-c++, cmake, ninja-build,
qt6-qtbase-devel, qt6-qtdeclarative-devel, qt6-qtwayland-devel, qt6-qtsvg-devel,
layer-shell-qt-devel, pipewire-utils, wireplumber and rpm-build.

```bash
cmake -S . -B build-package -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/usr
cmake --build build-package
ctest --test-dir build-package --output-on-failure
cpack --config build-package/CPackConfig.cmake -G DEB -B build-package/packages
# Use -G RPM for an RPM build.
```

DEB uses dpkg-shlibdeps for shared libraries and explicit runtime dependencies
for QML and dynamic plugins. Ubuntu splits the layer-shell and SVG plugins into
`layer-shell-qt` and `qt6-svg-plugins`. RPM uses automatic shared-library scanning
and Fedora runtime package names. Other RPM distributions may need dependency
name adjustments. Older distributions with LayerShellQt < 6.6 are unsupported.

The prefix must be /usr before configuration because the application launcher
embeds its executable path. CPack creates binary packages and a working RPM spec;
this is not an official distribution source package or an SRPM workflow.
The public project URL and maintainer contact ptrj <aur@dbs.sk> are configured.
Install using `sudo apt install ./package.deb` or `sudo dnf install ./package.rpm`.

## Arch/AUR preparation

```bash
bash scripts/prepare-arch-package.sh
podman exec mic-overlay-dev bash -euc \
    'cd /build/packages/arch && makepkg --cleanbuild --force --noconfirm'
```

Outputs are in `build-container/packages/arch/`. The preparation script creates
a source archive, PKGBUILD with its real SHA-256, and .SRCINFO. It verifies the
archive. `check()` runs backend/UI tests without a desktop session.
Only x86_64 is declared; aarch64 needs separate validation.

The Arch recipe uses the uploaded source archive asset from the versioned GitHub
Release, for example:

```text
https://github.com/ptrj/mic-overlay/releases/download/v0.2.2/mic-overlay-0.2.2.tar.gz
```

Upload the exact archive generated by the preparation script to the matching
GitHub Release. The URL is prepared; the asset is not created or uploaded by the
script. GitHub's automatically generated tag archives are different files and
must not be substituted without recalculating checksums and verifying layout.
Local preparation uses the generated archive already in makepkg's source cache,
so it can validate the checksum before the public release asset exists.

Before AUR publication, upload that release archive, use the generated PKGBUILD
with its real SHA-256 and .SRCINFO, verify the public download, and test a clean
Arch chroot build. The checked-in PKGBUILD is a preparation template; its SKIP
checksum must not be used for the AUR submission.
Submit only PKGBUILD and .SRCINFO, not binaries or archives. No publication is
performed by these scripts. The source archive excludes build directories,
local configuration, diagnostics and internal agent directories.

## Published AUR package

[mic-overlay](https://aur.archlinux.org/packages/mic-overlay) is maintained by
ptrj. Version 0.2.2-1 was published on 2026-09-27 using the source archive from
GitHub Release v0.2.2. The AUR repository contains only PKGBUILD and .SRCINFO.

The publication checkout is `build-container/aur-mic-overlay/`. For future
updates, publish the matching source archive first, update pkgver/pkgrel and the
checksum in PKGBUILD, regenerate metadata, verify the build, and push to master:

```bash
makepkg --printsrcinfo > .SRCINFO
git add PKGBUILD .SRCINFO
git commit -m "Update mic-overlay"
git push origin master
```

Initial publication was validated in a fresh Arch Podman container, downloading
all dependencies and the public source archive. Source checksums, generated
metadata and all four tests passed. Namcap found no errors after adding the
hicolor-icon-theme runtime dependency. This is isolated container validation;
a devtools chroot build remains a separate outstanding check.

## Installed-package checks

```bash
bash tests/package_smoke.sh deb
bash tests/package_smoke.sh rpm
bash tests/package_smoke.sh arch
```

These tests install packages only in temporary containers, verify the license,
launcher and configuration example, reject the offscreen platform, and launch
on real KWin for two seconds. They check PNG capture and SVG decoding errors.
Host packages are unchanged; session runtime is mounted read-only.
